# 隧道排障（SakuraFrp / 任何 TCP 隧道）

> 仓库里**不写真实公网地址、隧道 ID、访问密钥**（用户要求，避免泄露）。
> 真实参数只在用户自己的隧道面板 / 本机 `frpc/*.local.ini`（gitignored）里。

## 现在的形态

| 项 | 值 |
| --- | --- |
| 隧道类型 | `tcp` + 面板里开「**自动 HTTPS**」（不开国内节点会拦，见坑五） |
| 本机监听 | `127.0.0.1:7891`（**填 IP，不要填 localhost**，见坑四） |
| 公网地址 | 由用户面板分配（通常形如 `https://<节点域名>:<远端端口>`） |
| TLS | 在 frpc 那端终止，脱壳后仍是明文 HTTP 发给 7891 |
| 证书 | SakuraFrp「自动 HTTPS」现场生成的自签证书，访客第一次要点「高级 → 继续前往」 |

**访客地址必须带 `https://`。** 明文 HTTP 会被国内节点拦掉，回它自己的 501 页。
证书警告是用户明确接受的代价（想消掉要另有一个真域名 + 真证书 + 定期续期，D15）。

开关服务：`node tools/service.mjs start|stop|status|restart`（= 同名 `.cmd`）。

## 怎么判断"通了没有"

三种证据，按可信度排序：

1. ⭐ `data/server.log` 里出现 `[来访] ... host=<公网主机:端口>` —— **唯一硬证据**。
   没有这一行，节点就没把流量转过来，后面都不用查。
2. 本机 `127.0.0.1:7891/api/me` 返回 **401 + 我们自己的 JSON**
   （只看端口通不够，别的程序也可能占 7891）。
3. 公网 `GET /` 的状态码 / 标题 / TCP 耗时。

一条命令做完：

```powershell
node tools/check-tunnel.mjs <公网地址>
node tools/check-tunnel.mjs <公网地址> --ws 30   # 连打 30 次 WebSocket 握手
```

工具只读：不启停服务、不碰隧道、不写 `data/`。`--ws N` 统计"9 秒一个字节都没回来"的次数
（和 `shared/net/net.js` 的建连超时同一个数）。

### 四种典型症状

| 症状 | 意思 | 去看 |
| --- | --- | --- |
| **501**，页面写着"您正试图使用 HTTP 协议访问此隧道"，本机零来访 | 明文 HTTP 被节点合规策略拦住，字节根本没过来 | 坑五：开「自动 HTTPS」并改用 `https://` |
| **503**（SakuraFrp 的页面） | 节点侧没认这条隧道 / 域名 | 坑二：隧道名复用 |
| **502 / 连接被拒** | 转到本机了但本机没答（端口填错 / 服务没开） | 启动器日志搜「连接映射目标」 |
| 面板"在线"、frpc 日志"启动成功"，但访问 503 | "在线"只代表你电脑上的 frpc 连上了 | 坑二 |

启动器日志：`C:\ProgramData\SakuraFrpService\Logs\SakuraFrpService.<日期>.log`。
出现 `连接映射目标 ... 连接被拒绝` 就是本地端口填错了。

## 踩过的坑（别重复踩）

### 坑一：隧道类型必须和本地服务的协议一致

我们的服务端**永远只讲明文 HTTP**（TLS 交给外层）：

| 隧道类型 | 能不能用 | 为什么 |
| --- | --- | --- |
| `tcp` + 面板开「自动 HTTPS」 | ✅ 现在用的 | frpc 用 TLS 对外收连接，脱壳后明文 HTTP 连 7891 |
| `tcp`（不开自动 HTTPS） | ❌ | 国内节点直接拦明文 HTTP（坑五） |
| `https` | ❌ | 它要求本地服务自己讲 HTTPS：TLS 原始流量丢给只会 HTTP 的 7891，握手失败，本机零日志 |
| `http` | ❌ 现在 | 只在非内地节点可行（内地建站要 ICP 备案） |

### 坑二：隧道名**不能复用**（真正的拦路虎）

旧隧道虽然删了，节点上可能还挂着**同名的旧代理**，新隧道被顶掉 ——
面板显示"在线"、frpc 日志"绑定成功"，但节点不认，所有人拿到 503。

**解决办法**：换个名字 + 删掉重建 + 重启启动器。
**501/503 甩不掉时，优先怀疑"节点上还挂着旧的同名登记"，换名字重建比调参数快。**

### 坑三：Cloudflare 加密模式必须和隧道类型匹配（HTTP 隧道时代）

| 隧道类型 | Cloudflare 加密模式 | 设错的表现 |
| --- | --- | --- |
| HTTP 隧道 | **灵活** | 设成「完全」→ 525 |
| HTTPS 隧道 | 完全 / 完全（严格） | 设成「灵活」→ 503 |

现在这条 `tcp` 路**不经过 Cloudflare**，只在切回 `frpc/http/` 时才有意义。

### 坑四：本地 IP 别填 `localhost`

Windows 上 `localhost` 会先解析成 IPv6 `::1`，而服务只监听 IPv4 `127.0.0.1`。
填 `127.0.0.1` 少一层解析、少一个隐患。

### 坑五：国内节点**禁止明文 HTTP**（最常撞）

症状：`http://...` 返回 **501**（SakuraFrp 自己的合规页），本机 `data/server.log` **零来访**，
启动器日志完全正常。三个实验钉死：

| 往公网地址发什么 | 结果 |
| --- | --- |
| 明文 HTTP | 节点回它自己的 501 页，不转发 |
| 一段非 HTTP 字节 | **原样转发到本机 7891**，我们的服务回 400 |
| TLS 握手 | 也转发到本机（但本机不讲 TLS，所以失败） |

**解法（一步）**：面板编辑隧道 →「自动 HTTPS」选 `自动` → 保存 → **重启隧道**，
之后一律用 `https://`。原理是 frpc 用 TLS 收连接、脱壳后用明文连本地 ——
所以**服务端代码一行都不用改**，`shared/net/net.js` 按页面协议自动选 `ws://` / `wss://`。

### 坑六：改 `frpc/*.ini` **不等于**改了隧道

真正的参数由**面板**决定；启动器连上节点时自己生成 frpc 配置。
仓库里 `frpc/` 只是归档模板，改它们不影响线上。
换端口 / 换隧道一律去面板改、改完重启启动器。

## 已知遗留风险（用户知情接受）

1. 访客会看到自签证书警告，第一次点「继续前往」。
2. 公共地址带端口（免费隧道远端端口是随机分配的），发给别人别漏端口。
3. 节点是单点；停用的 HTTP 通道（`frpc/http/`）留着，需要时可临时切回。
4. frpc → 本机 7891 那一段是回环明文，不构成外部风险。
5. 限速约 10 Mibit/s：游戏资源要小，别默认全量预加载。

## 不要用的方案（都试过/查过）

1. **免费 `nyat.app` 子域名**：已开 HSTS Preloading，不开 HTTPS 会完全打不开。
2. **把 TCP 隧道套在 Cloudflare 后面**：免费版只能送 80/443，TCP 必须带端口。
3. **给服务端加 HTTPS**：直接违背硬约束，TLS 该由 frpc 终止。
4. **内地节点的 HTTP(S) 隧道**：内地建站要 ICP 备案，没有备案就用不了。
