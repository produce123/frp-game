## 2026-10-26 狼人杀：一轮审计后的修改（空选 / 遗言 / 白痴 / 狼队频道 / 增量消息）

**起因**：用户要求"审计一遍狼人杀有没有 bug / 逻辑漏洞 / UI 错误"，我列了高/中/低三档清单，
他逐条拍板。**唯一没修的是 L4（恶夜骑士反伤被当夜已死的人白吃）** —— 见 `docs/NEXT.md`。

**用户拍板的规则（都已完成）**

| 要求 | 落地 |
| --- | --- |
| 白天能弃票 | 放逐投票 + 警长投票都加了「弃票」按钮（服务端本来就认 `seat:null`，只是界面没给入口） |
| 狼人夜里能私下交流 | 新的 `wolfChat` 动作：消息带 `scope:'wolf'`，**只发给狼**（好人的报文里根本没有这些条目），界面在狼队面板里 |
| 夜里死的人要有遗言 | 天亮公布死讯之后进 `DAY_LAST_WORDS`（天亮 → 死讯 → 遗言 → 猎人开枪 → 移交警徽 → 讨论） |
| 白痴翻牌后再被投出**不再死** | 翻牌后免疫是"牌面已公开"的状态，不受长老封印影响；第二次被投出只播报"本轮放逐无效" |
| 所有行动都能空选（含预言家空验） | 守卫空守、狼人空刀（撤票）、狼美人空过、预言家空验；**空选不能写成 `Number(null)=0`**，会误查 0 号 |
| 发言可以连发多段 | 引擎本来就支持（`speech` 不换人）。真正的问题是**输入框按 Esc 会结束发言**，想把这一段说完的人一击就把麦交了 → Esc 现在只关 @ 候选 |
| 各阶段时长**维持现状** | 发言 180 / 夜间 60 / 投票 60，`DURATION` 一个数没动 |

**顺手修掉的真 bug**（每条都有回归用例）

- **夜里守卫那晚是空白面板**：`currentSpeaker` 会退化成"最后一条非系统消息"，夜里的旧发言把提示顶掉了；
  现在只有 `DAY_*` 阶段才拿它当发言人，并且给"轮到你行动"单独一块提示 + 一个「不选」按钮。
- **白痴免疫永远算不出来**：前端用 `roleAbilities.idiotRevealed && role === 'Idiot'` 找翻牌者，
  而别人的 `role` 根本不下发（被 `p.role || 'Villager'` 兜成平民）→ 服务端直接把 `idiotRevealed` 放进公开视图。
- **投票进度条分母错**：PK 复投时台上的人不算投票人（服务端也这么算）；已翻牌白痴同理。
- **投票结果卡片显示人头数、系统消息显示 1.5 票**：卡片改用服务端给的 `weight`。
- **警长死了但遗言/开枪/殉情那条路径不会移交警徽**：抽了 `badgeIfDead()` 一个入口，
  四条"人是被技能带走的"路径都接上（猎人带走、白狼王带走、骑士决斗、狼美人殉情）。
- **空守之后"隔一晚也不能守同一个人"**：空守要把连守记录清掉。
- **狼美人魅惑跨夜不清**：`enterNight` 统一清 `charmedSeat`（以前白天结算会读到上一夜的旧魅惑）。
- **长老被毒死时提前封印好人技能**：毒药循环里那行 `goodSkillsDisabled` 删掉，只在公布死讯时设，否则 NIGHT_RESOLVE 那 3 秒等于泄密。
- **夜里死的人说不了遗言**：`viewFor` 在 `!me.alive` 提前 return 之前没给 `can.speech`，界面上不给输入框，只能干等 180 秒。
- **有人正在打的局，点别的房间会被拽走**：`joinRoom` 会先 `leaveRoom`；现在开局后 `leaveRoom` 拒绝，整条链就拒绝了（大厅里换房仍然允许）。
- **房间扫除没人调**：`sweep()` 原本没有定时器，12 小时没人管的房间一直在内存里；`server.mjs` 每分钟扫一次。
- **每 5 秒把整局历史重发一遍**：`/game/status` 支持 `?since=<seq>`，前端按 id 合并增量消息（以前手机上几百条消息每 5 秒重下）。
- **大厅写着 `**不能中途加入**`**（markdown 星号没渲染）、房主**踢不了掉线的人**（新增 `/room/kick`）、
  点玩家头像**没反应**（现在弹一句公开信息）。

**踩的坑**

- 引擎测试的两个"假用例"（`assert.ok(ended.length >= 0)`、只等一个阶段就结束）换成了真断言 ——
  改这类用例时会发现**前一个用例失败留下的定时器会污染后面的用例**（表现为无关用例随机失败）。
- 真浏览器里测"连发两段"时，`page.type` 逐字派发太慢，会把发言倒计时耗光 → 假失败；
  改成一次 `execCommand('insertText')`，并且**断言一律"等 DOM"而不是拿接口状态直接断言 DOM**（页面更新是异步的）。

**用户的要求**（原话拆成两条）：
1. 现在"狼阵营 = 好人阵营就判狼人获胜（狼控场）"不对：**1 狼 2 好人**、其中一个是**没翻过牌的骑士**，
   狼夜里刀掉另一个好人后，骑士本该在投票前翻牌决斗把狼带走 → 好人能赢。所以**不许提前结束**，
   要一直打到一方死光，而且"立刻"是指**死讯一结算就判**（1 狼 1 猎人被刀死 → 当场狼胜，猎人开不了枪）。
2. 开房不再强制"至少 1 个狼人 / 白狼王"，改成**至少 1 个狼阵营角色**。
3. 顺带引入新概念：房主建房时选 **屠边局 / 屠城局**。

**最终规则**

| 模式 | 狼人怎么赢 |
| --- | --- |
| 屠边（默认，经典） | 杀光所有**平民**，或杀光所有**神职**（所有非平民的好人） |
| 屠城 | 杀光所有**好人** |

- 好人胜 = 狼人全灭；**双方同一刻全灭时判好人胜**（典型：1 狼 1 女巫，狼刀女巫、女巫毒狼）。
- 删掉了"存活狼人 ≥ 存活好人"的狼控场判定。
- 屠边局建房时**必须同时配 ≥1 平民和 ≥1 神职**，少一边直接**不让开房**并提示；
  屠城局不限（0 平民也行）。校验在引擎 `validateRoleSetup(seats, roles, winMode)` + 前端 `checkCounts` 各做一遍。
- 开房门槛：`isWolfRole` 五种（狼人 / 白狼王 / 狼王 / 狼美人 / 恶夜骑士）任意一种即可。

**证据**

- `node --test tests/werewolf.engine.test.mjs` → 39/39；`npm run test:werewolf` → 50/50（含浏览器）；
  `npm test` → 171 条、170 过、1 跳过。
- 真机（真实 7891 + 真实 dist，4 个新账号）：
  屠边缺平民 → 弹窗红字 + 「创建房间」置灰；同一配置切屠城 → 立刻可建；
  **只放 1 个狼美人**（没有狼人/白狼王）→ 开房成功、等候区显示"屠边"；
  屠边第一夜刀掉唯一的平民 → **立刻狼胜**（女巫/预言家/狼美人还活着）；

**踩的坑**

1. 老用例用"配 1 个平民的 7 人局"测骑士/守墓人，屠边默认规则让第一晚就结束 → 报 `等状态超时，最后是 GAME_END`。
   这些用例的目的是测技能，给它们显式传 `winMode: 'wipe'` 就行，不要为此改引擎。
2. `DAY_START` 只是"给客户端播死讯的 4 秒缓冲"，**死讯要到 `announceDeaths` 才真正 `kill()`**；
   实测脚本里用 `phase.startsWith('DAY_')` 当"天亮后"来断言，会读到"还没有人死"的中间态。
   要等 `phase !== DAY_START`（或者直接等 `GAME_END`）。
3. 真机上 `document.cookie` 读不到 `sid`（HttpOnly），房主的 API 身份得走 CDP `Network.getAllCookies`；
   而且注册完会跳回 `/werewolf/`，那里没有平台外壳的 `window.GameNet`，别等它连上。

2. **`tsc` 的默认值会变**：`moduleResolution=node10` 已被 TS 7 移除（TS5108）；

3. **`import io from "…/io"` 有两种写法**：正则批量替换漏了 `"../../../"` 与 `"../../"` 两级，

4. **`base: '/werewolf/'` 之后模板里的 `/assets/x.svg` 全都 404**：上游写的是站根绝对路径，

6. **`Room.clearAll()` / `clearRoom()` 原来不 `clearTimeout`**：房间从表里删掉之后，

   这是**这一轮唯一一处上游的真空转 bug**。

8. **`roomInit` 的公开名单里没有 `_id`**（`getPublic` 只给座位/昵称/头像）——

9. **Vue 单文件里不能 `require()`**：等待房想复用角色简介时写了

10. **平台的邀请卡只在平台首页挂载**：玩家在 `/werewolf/` 页面里时那段脚本根本没加载，

### 追加：深链必须"直接进房"，不能停在首页/连接中

好友同意邀请后浏览器会打开 `/noname/?frpJoin=房号`，但原实现是"切联机模式 → 点连接"，
结果人先看到无名杀首页，还要自己点「联机 → 连接」；点完又卡在 `正在连接 wss://…`。

**根因**：`game.switchMode('connect')` 会走完整的联机模式 UI 初始化，菜单/教程的异步收尾
和深链抢执行顺序；`connect2` 把 `ui.iptext` 改成「正在连接...」后，成功回调**不恢复文字**，
所以看起来一直卡着。

**改法**：桥接拿到 `frpJoin` 后**不再碰联机模式 UI**，直接：

1. 写 `tmp_user_roomId = 房号`（必须在连接前，大厅 `roomlist` 一到就消费）；
2. 补 `lib.configOL.bannedcards/banned/mode`（直连跳过了联机模式初始化，不补会在
   `roomlist → clearArena → ui.create.cards` 抛异常，房间列表建不出来）；
3. `game.onlineKey` 自己初始化，`game.connect(lib.hallURL)`；
4. 大厅握手后 `roomlist` 自动 `enter` 房号，**全程没有 IP 界面、没有「正在连接」**；
5. 首次向导若盖在房间上，只把 `ui.dialog` / `ui.controls` 设成 `display:none`，
   **不点跳过、不 close、不 reload**（点/close 会让身份局教程继续清场，把房间冲掉）。

另外把昵称/头像同步从 boot 主流程拆出去：它等 `ui.menuContainer` 最多 30 秒，
在"上次停在联机模式、主菜单根本不建"的情况下会把自动进房一起拖死；进房前桥接自己
直接写 `connect_nickname/connect_avatar`。`check-noname` 现有布局/身份断言保持全绿，
深链这条用临时脚本（真 Chrome + 真中继 + 真房间）实测后已删，避免把一次性调试脚本留在仓库。

## 通道切换：Cloudflare/HTTP → 国内 TCP（2026-10-21，✅ 已完成）

**用户的两条要求**：① 暂时关掉 HTTP 通道（**代码保留**，等以后有公网 IP 再开）；
② TCP 与 HTTP 的配置**分文件夹**存放。

**为什么换**：Cloudflare 免费版把中国大陆访客甩到**洛杉矶**边缘节点 ——
实测 `https://<你的域名>/` 首字节 **1.34 秒**、返回 **503**（`CF-RAY: …-LAX`），
直连日本节点也是 503；另有一条老毛病"约 12% 新建连接卡满 60 秒"。

**最终形态**：隧道 `TCP`（id `<隧道 ID>`、类型 `tcp`、远端端口 `<端口>`、节点 `yd.<节点域名>`）
+ 面板里开的「**自动 HTTPS**」。访客地址 **https://<你的公网地址>**。

**⭐ 这一轮最大的发现（大半时间花在它身上）**：**国内节点会拦截明文 HTTP。**
症状极具误导性 —— `http://<你的公网地址>` 回 **501**（是 SakuraFrp 自己的合规页，
正文写着"您正试图使用 HTTP 协议访问此隧道…请启用 HTTPS 后使用 HTTPS 访问"）、
**本机 `data/server.log` 一条来访都没有**、而启动器日志一切正常。
破解靠三个实验（完整记录在 `docs/TUNNEL.md` 坑五）：明文 HTTP 被拦；
**非 HTTP 的字节被原样转发到本机**（我们的服务回了 `400 Bad Request`）；TLS 字节也转发。
→ **隧道是好的，被拦的只是"明文 HTTP"这一类。**

**解法**：面板里开「自动 HTTPS」—— **TLS 在 frpc 里终止、脱壳后仍用明文 HTTP 发给 7891**，
所以**服务端代码一行都没改**（也正因此没有违背"服务端只讲明文 HTTP"那条硬约束）。
官方速查表原话：*"网页（国内节点）→ ✔️ 必须"*。
中途还撞过一次 `docs/TUNNEL.md` 坑二（旧隧道 `TCPgameweb` 的本地端口被写成 8719，
改回来之后仍不通，最后**换名字重建**才干净）—— 过程记在坑二里。

### 上一轮踩到并修掉的真 bug

## 更早修掉的真 bug（都有回归防线了）

1. **游戏页面从来没连过 WebSocket。** 平台首页是 `web/assets/js/app.js` 调的 `connect()`，
   游戏页面没有那个文件 —— 界面上什么都画得出来、控制台一声不响，
   但点"创建房间"永远没反应。修法：`FrpRoom.mount()` 里代劳。
   防线：`check-game.mjs --browser` 现在要求"真的连上 + 真的建出带房号的房间"。
2. **点好友列表的「进入」只跳页、不买房。** 原来以为"服务端会把房间状态补发过来"就够了，
   但补发只对**已经在座位上的人**（断线重连）成立。修法：把房号放进
   `?join=XXXXXX`，由 `FrpRoom.mount()` 自动入座。
3. **离开房间的人收不到任何消息。** 房间层只给还留在房里的人广播，
   离开的人界面就一直停在房间里（"点了离开没反应"）。修法：单独给他补一条
   `{t:'room.state', code:null}`，客户端靠 `code` 是否为空判断"我在不在房里"。
4. **服务端的拒绝在游戏页面里完全静默。** 平台首页会弹提示，但游戏页**不加载**
   `web/assets/js/app.js`，共用房间外壳又没监听 `T.ERROR` —— 服务端每拒一次
   （"还没轮到你"、"开局失败：…"）都是"点了没反应"，控制台也一声不响。
   修法：把监听加在 `shared/ui/room.js` 的 `mount()` 里（一处修好、三个游戏受益），
   并**删掉游戏里自己补的那两条重复监听**（不删会弹两条一样的提示条 —— 刀马真撞到过）。
   防线：三个游戏的浏览器用例都断言"提示条出现了"，刀马那条还断言**恰好 1 条**。
5. **平台首页的登录竞态。** 页面刚打开就以毫秒级速度提交登录时，`boot()` 里探测
   `/api/me` 的 401 会迟到，把界面**翻回登录页**（实际已登录）。
   修法：`authEpoch` 纪元 —— 登录/注册后 +1，在途的旧探测结果一律作废。
   防线：`tests/login-race.browser.mjs` 用 CDP 把 `/api/me` 扣住，把这个竞态拉成 100% 命中。
6. **公网建连会卡满 60 秒。** 见"已知的小毛病"第一条 ——
   2026-10-21 换到国内 TCP 后已不复现，但**那三层兜底保留**。
   修法：客户端加 **9 秒建连超时**（到点摘掉 socket 再走现有退避重连）。
   防线：`tests/net-timeout.test.mjs` 用"收到 upgrade 却永远不回话"的假服务器钉着。
7. **体检工具自己的判据写错了。** `tools/check-game.mjs` 判点击目标用的是
   `高<44 && 宽<44`（两个都小才算），于是"宽 326px、高 42px"的整行按钮一直漏检 ——
   房间准备区那个「编辑初始位置」就是这么躲过体检的。
   修法：改成"任一边小于 44"，复选框/单选框按包着它的 `label` 量。收紧后三个游戏依然全绿。

顺手还统一了两件事：屏幕的当前标记统一成 **`.screen.is-active`**
（大炮轰小鬼原来叫 `active`），以及 `check-game.mjs` 里**再没有任何具体游戏的类名**
（它原来是照大炮轰小鬼硬编码的，第二个游戏搬进来就被卡住了）。
