## 四种内容各自该放哪

1. **设计决定**（含"为什么"和"被否掉的选项"）→ `DECISIONS.md`，编号往后排（现在是 D52）。
   被后来的决定取代时：正文搬进 `archive/DECISIONS-superseded.md`，原位留一行指针。
2. **架构与协议** → `ARCHITECTURE.md`。加协议消息要**同时**改三处：
   `shared/protocol.mjs` 的 `T`、本文件的消息表格、`server/hub.mjs` 的 `dispatch`。
3. **某件事是怎么修过来的** → `HISTORY.md`，只追加、倒序、带标题。
4. **现在还成立的事实**（现状 / 下一步 / 环境事实 / 小毛病）→ `NEXT.md`。
   `NEXT.md` 只留结论，过程搬 `HISTORY.md`。

## 写作约定

- **不删结论，只搬位置**：任何一条"当时为什么这么做"都必须还能找到出处；搬走要在原地留指针。
- **数字只认实测**：测试条数以 `npm test` 的输出为准（现在是 199 条：198 通过 / 1 跳过）。
  别在文档里写"应该可以"。
- **日期口径**：本机时钟显示 2026 年（见 `NEXT.md` 的环境事实），文档里的
  「2026-11」这类是**轮次标签**，不是精确日历；对不上不用去改。
- **公网地址、隧道密钥、数据库、头像绝不进仓库**（已 gitignore）。
- 用户不是程序员：结论用大白话，给选项时给**推荐项 + 代价**，并说清"用户看到什么变化"。
