# Shell Gambit · 恶魔轮盘聚会版

一个**霰弹枪轮盘**聚会小游戏：2–4 人围着一张桌子，
弹匣里实弹空弹混装，**你知道里面各有几发，但不知道下一发是什么**。
轮到你时要么冲自己开一枪（空弹保留回合，能继续操作），要么冲别人开一枪。
最后活着的人赢。

> 灵感来自《Buckshot Roulette（恶魔轮盘）》。
> 这是它接入 frp-game 平台之后的版本：**服务器是唯一权威**，
> 原来的公共 MQTT + WebRTC 那一整套已经全部删掉（见文末）。

## 怎么玩

在平台首页点 **Shell Gambit 💀** 的卡片进游戏页，三个入口：

| 入口 | 说明 |
| --- | --- |
| **人机对局** | 完全在你自己的设备上跑（断网也能玩），选 2 / 3 / 4 人局，其余席位由 AI 补齐 |
| **在线对局** | 创建房间 / 输入 6 位房间号加入；**一个人也能开局** —— 按一下平台准备的「＋ 添加人机」就多一个电脑座位，座位够了「开始游戏」才亮（**人机也算座位**） |
| **游戏规则** | 完整规则与 7 种道具说明（游戏内也有一份） |

**不需要登录/取名以外的任何东西**：名字和 ID 直接来自平台账号，
游戏里不会再问你要名字（平台 `DECISIONS.md` D5）。
首页和房间里的在线状态、好友邀请都是平台外壳的能力。

首页底部可以自己开关 **音效** 与 **特效**（对局中的「☰ 菜单」里也能改），
开关状态记在浏览器本地。关掉特效后仍保留文字事件流与中央横幅提示，不会失去任何信息。

### 在线对局步骤

1. 平台首页注册/登录 → 点 Shell Gambit 卡片 → 【在线对局】。
2. 房主点【创建房间】，把 **6 位房间号**念给朋友（点房间号可以直接复制）。
3. 朋友用同样的路径进【在线对局】→ 输入房间号 → 【加入】。
4. **想一个人先开一局**：按一下「＋ 添加人机」—— 列表里立刻多出一个电脑座位
   （灰头像 +「人机」标签，名字是**一个字**：虎、狼、鹰…）。
   座位数到 **2** 之后【开始游戏】才亮得起来；只有你一个人、又没有电脑座位时，
   那个按钮是**灰的**，旁边写着"至少要 2 个座位才能开始（现在 1 个）"。
   （真有人从控制台硬发开局命令，服务端也会拒绝并在界面上弹提示条 —— 不是静默失败。）
5. 人机的座位在牌桌上的圆环是**灰色的**：自己=蓝、其他真人=橙、人机=灰。
   想换人/加人：房主可以对着人机点「移除」，或者继续按「＋ 添加人机」（最多 4 个座位）。
6. 本作**不支持中途加入**（发出去的牌收不回来，规则上做不到公平）。
   开局之后有人离开，他的座位由电脑接管，这一局照样能打完。

> ⚠️ 房间的**成员列表里真人和人机都在**（人机那行带「人机」标签、头像灰环），
> 所以"座位满了没"一眼就能数出来：座位 **2–4** 个就能开局，上限 4 个。
> 人机由房主加、也只能由房主移除。

## 规则

### 基础玩法

- 2–4 人，每人 **5 点生命**，开局**随机**分配 1–4 号座位。
- 每一**轮**随机装填一批「实弹 / 空弹」混合弹序。
  **两种弹药各剩多少是公开信息，先后顺序严格保密。**
- 每轮由**最小座号的存活玩家**先行动（1 号已出局则由下一个存活座位开始）。
- 轮到你时：先摸牌，然后选择【对自己开枪】或【对别人开枪】。
- **空弹打自己**：不掉血，并且**保留回合**，可以继续操作（这是核心博弈点）。
- **实弹命中**扣 1 点血；锯短枪管时扣 2 点。血量归零立即淘汰。
- 弹匣打空后自动重新装填，回到新一轮。
- 最后活下来的唯一玩家获胜。

弹药数量规则：总发数 = 人数 × 2 ～ 人数 × 3 之间的随机数，
实弹发数在该总数内随机，但**至少 1 发**、且**至少留 1 发空弹**。
（例如 4 人局可能是 8～12 发，其中实弹 1～11 发。）

### 摸牌规则

- 牌堆共 **28 张**：7 种道具 × 4 张。
- 开局每人 2 张；之后每个回合摸 2 张，**全局第一回合只摸 1 张**。
- 手牌上限 **4 张**：回合开始前已有 3 张就只发 1 张，已有 4 张则不发。
- 摸牌堆少于 4 张时，弃牌堆洗匀后放到摸牌堆**底部**（不是顶部，避免刚弃的牌立刻被摸到）。
- 玩家被淘汰时，其手牌全部进入弃牌堆。

### 7 种道具

| 道具 | 效果 |
| --- | --- |
| 🔍 **放大镜** | 查看当前这一发是实弹还是空弹（**只有你能看到**） |
| 🔄 **逆转器** | 反转当前这一发子弹的真假（实弹↔空弹） |
| 💉 **肾上腺素** | 从一名对手手中**随机偷取**一张道具并**立刻使用** |
| 🍺 **啤酒** | 退出当前枪膛里的第一发子弹（**子弹类型公开**） |
| 🪚 **手锯** | 锯短枪管：下一发实弹伤害翻倍（打出空弹则浪费） |
| 🚬 **香烟** | 恢复 1 点生命值（上限 5，满血使用则浪费） |
| ⛓️ **手铐** | 封锁一名对手的下一回合 |

### 容易记错的细节（本作的明确裁定）

这些地方原版规则有歧义，本项目做了明确处理，并且每条都有单元测试覆盖
（`tests/rules.test.mjs`）：

- **放大镜**的情报是私有的，对手看不到。
- **逆转器**是公开动作：原本知道这一发的人，会同步知道它被反转了
  （否则先看再转就成了单向作弊）。
- **啤酒**退出的子弹类型是公开的（大家都能听到退弹的声音）。
- **手锯**只对下一发有效，**打出空弹也会浪费**；已经锯过时不允许重复锯。
- **香烟**满血使用等于浪费一张牌。
- **肾上腺素**偷不到对手的肾上腺素（防止无限递归）；
  偷到**手铐**时会再让你**选一次目标**；
  偷到的牌若**没有合法目标**（例如所有人已被铐住），则该牌直接进弃牌堆。
- **手铐**不能铐自己，也不能铐已经被铐住的人。
  被铐住的人**回合一开始就被跳过**，手铐在跳过的那一刻消耗掉，回合顺延给下一位能行动的人；
  如果除当前行动者以外的所有人**都被铐住 / 都被跳过**，回合**回到当前行动者身上**
  （2 人局里就是「他打完你、你被跳过、他接着打」），
  被跳过的人只能丢掉这一回合，**不会反向拿到一个回合**。
  手铐若一直没轮到消耗（例如弹匣先打空换弹了），会保留到下一轮继续生效。

## AI 是怎么想的

AI 与真人**看到的信息完全一样**：只有公开的血量、手牌张数、剩余各类弹药数量，
以及自己用放大镜看到的结果。它**读不到弹匣顺序，也读不到别人的手牌**，
**更不知道谁是真人、谁是 AI** —— 因此不会针对或保护任何人。

`aiDecide(state, playerId)` 与 `aiDecideFromView(view)` 共用同一个决策核心
`decideFrom()`，所以「AI 作弊」在结构上就不可能发生。
服务端跑的是后者（只喂裁剪过的视图）。

决策方式是对每个合法动作算期望值，主要考虑：

- **保留回合**的价值（空弹打自己能继续行动，是非常强的节奏）
- **击杀**收益、**自己掉血**的风险（血越少越保守）
- **威胁评估**：血多的、手牌多的、即将轮到的人更该被打
- **记仇**：被谁打过就略微更倾向还手，但**只是一个小权重**，会被局势分析覆盖
- 一点点随机噪声，避免每局都一模一样

```
games/shell-gambit/
├── index.html            单页应用：所有界面都在这一个文件里
├── css/style.css         暗色极简样式（原项目视觉稿 + 平台适配覆盖）
├── js/
│   ├── engine/           游戏引擎（完全不碰 DOM，Node 里也能跑）
│   │   ├── constants.js  规则常量、道具定义
│   │   ├── rng.js        可复现的随机数（mulberry32）
│   │   └── engine.js     状态机：装弹、发牌、7 种道具、回合与轮次、视图裁剪
│   ├── ai/ai.js          AI 决策（只吃公开信息 + 自己的私有情报）
│   ├── view.js           viewFor 的唯一入口（页面和服务器都从这里取）
│   ├── ui/
│   │   ├── app.js        屏幕切换、身份、单机开局、在线对局的挂载与渲染
│   │   ├── match.js      单机对局的驱动器：真人提交 + AI 补跑（含思考延时）
│   │   ├── board.js      牌桌渲染（只吃裁剪过的视图）
│   │   ├── icons.js      内联 SVG 图标（无图片文件）
│   │   ├── audio.js      WebAudio 现场合成音效（无音频文件）
│   │   └── effects.js    飞行动画、枪口火光、伤害数字、横幅
│   └── main.js           入口
└── tests/
    ├── rules.test.mjs    47 条：规则 + 视图裁剪 + 服务端接入层
    ├── ai-fill.test.mjs  15 条：人机**座位**（1 人+1 人机座位打完整局、
    │                     真人视图里 AI 身份可判定、满桌 1+3、真人/人机混合桌、
    │                     座位表原样交给引擎、字段哨兵、removePlayer / addPlayer）
    ├── sim.mjs           AI 自对弈压力测试（不变量 / 覆盖率 / 胜率均衡）

server/games/shell-gambit.mjs   平台接入层：meta + createMatch（权威逻辑跑在这）
```

**零运行时依赖、零构建步骤**：没有 `node_modules`、没有打包器，
所有 `js/**` 都是浏览器可以直接加载的 ES Module（`engine/**` 与 `ai/**`
另外还被服务器直接 import，所以那两个目录里**不许出现 `document` / `window`**）。

## 测试

在仓库根目录跑（`E:\frp-game`）：

```bash
node --test games/shell-gambit/tests/rules.test.mjs   # 规则 + 裁剪 + 接入层
node --test games/shell-gambit/tests/ai-fill.test.mjs # 人机座位专项
node games/shell-gambit/tests/sim.mjs                 # AI 自对弈
node games/shell-gambit/tests/browser.e2e.mjs         # 真浏览器端到端（需 Chrome/Edge）
```

也可以先 `node server/server.mjs`（本机 7891），再从平台首页点卡片进去手动玩一遍。

验证涵盖：

- **规则正确性**：7 种道具的每个分支、牌数守恒（28 张永远不多不少）、
  边界与非法操作、以及「死锁」这一永久不变量。
- **视图裁剪**：逐字段核对每个座位的视图，确认**报文里不含弹匣顺序、他人手牌、
  他人的放大镜情报**（并把 JSON 当字符串搜一遍，任何未公开字段名都不许出现）。
- **AI 自对弈**：每种人数 3000 局随机对局，不允许出现非法动作、死锁或状态损坏；
  胜率必须接近理论值（2 人 50/50、3 人各 1/3、4 人各 1/4），以此证明没有位置偏向。
  另外单独跑 600 局"AI 只吃 `viewFor` 结果"的对局 —— 证明服务端那条路是走得通的。
- **人机座位**（`ai-fill.test.mjs`）：**人机是房间的座位**（`players[].isBot === true`），
  一个真人 + 一个人机座位能从开局打到结束、中途不需要真人去"催"服务端
  （每一步之后回合都不许停在人机身上 —— AI 必须在 `createMatch` / `act()` 返回之前跑完）；
  1 真人 + 3 个人机座位（满桌）也能开局；真人与 2–3 人的混合桌标记各归各位；
  座位表**原样**交给引擎（不截断、不兜底、不多造，垃圾 `options` 一个字段都不读）；
  真人视图里 `players[].isAI` 与座位一致（界面靠它画灰圆环），而人机的隐藏信息
  （手牌、放大镜情报）逐字段核对过、不进真人的报文；真人离开 / 人机座位被
  `removePlayer` 的行为。
  另有 **字段哨兵**：座位条目的字段**恰好**等于 `PUBLIC_PLAYER_FIELDS`
  （`isAI` 在、房间层的 `isBot` / 引擎内部的 `isAi` 都不在）。
- **真实浏览器**：两个无头 Chrome 实例走完「注册 → 进游戏页 → 人机对局真的走一步 →
  建房 → **一个人时座位 1 / 4、「开始游戏」灰着** → 绕过灰按钮硬发一条开局命令 →
  **服务端拒绝、界面上弹出提示条** → **按「＋ 添加人机」→ 多一个灰环人机座位 →
  开局、真的等到"轮到我"** → **牌桌头像逐个体检**（`data-frp-avatar` / 52px /
  自己蓝 + 人机灰）→ **点下去本机不演**（同一次页面求值里量到 `room.act` 0→1，
  而火光 0→0、WebAudio 振荡器 6→6、记录/横幅/seq/动作区一个字没变）→
  **逐条演出**（一次回包的事件分 5 次长起来、间隔 432–628ms）→
  **演出期间点不动**（队列忙时把屏幕上所有动作按钮和手牌全 `el.click()` 一遍：
  `room.act` 1→1 一条都没发出去，按钮 `pointer-events: none` / `opacity: 0.45`）→
  再走一步 seq 真的变大 → 再建一间房 → **第二个真人用房间号加入** → 房主开局 →
  两边看到同一帧服务器视图」，并检查控制台零报错。
- **界面自适应**：430×932 与 360×640 两种视口下
  校验无横向溢出、元素不跑出屏幕、按钮点击区域不小于 44px。
- **平台机械体检**：`node tools/check-game.mjs shell-gambit --browser`
  （引擎零 DOM、`index.html` 脚本顺序、`meta`/`createMatch` 契约、
  跑本目录的 `tests/*.test.mjs`、再跑一遍真浏览器用例）。
  浏览器那一段**只用平台契约**（页面起得来、真的连上、点【创建房间】真的拿到房号），
  不再要求任何"本游戏自己的类名"。

## 和原项目的差别（搬进平台时改的）

原来的 Shell Gambit 是**纯前端、零服务器**的：靠公共 MQTT broker 配对 +
WebRTC DataChannel 直连，房主是权威端，还用 QoS0 补偿和 2 秒全量重放来兜丢包。
平台有一条自建 WebSocket 与一套账号/房间系统（`DECISIONS.md` D1/D2/D4/D5），
所以：

- **`js/net/**` 整个删掉**（`mqtt.js` / `channels.js` / `rtc.js` / `session.js` /
  `protocol.js`，约 64KB），换成 `shared/net/net.js` + `shared/ui/room.js`。
- **权威端从"房主浏览器"搬到服务器进程**：游戏模块 `server/games/shell-gambit.mjs`
  直接 import 同一份 `engine.js`，客户端只能发"意图"、只能收裁剪过的视图。
- **不再问玩家名字**，也不再自己画房间界面（房间号、成员、邀请都是平台组件）。
- **删掉花朵 / 鸡蛋互动**：它是"没有服务器时顺手做的一条广播通道"，
  而平台协议里没有这条消息类型（要加得改 `shared/`，那是平台的文件）。
  **现在由平台接管**：牌桌头像带上 `data-frp-avatar` 就自动可点（扔鸡蛋/鲜花、
  抛物线、两端同步都是平台的能力），本作一行都没写。
- **掉线不判负，座位由 AI 接管打完这一局**：本作状态全在服务端，
  掉线就判负的话剩下的人会拿到一局死棋。
- **在线房间一个人也能开局**（人机是**房间的座位**）：`meta.minPlayers = 1`（真人下限）、
  `meta.minSeats = 2`（总座位下限，人机也算）。房主按平台外壳画的「＋ 添加人机」加座位，
  座位数随 `room.state` 同步给两边；`createMatch` 只把 `players` 里
  `isBot === true` 的座位当成 AI 座位 —— 游戏这边**不造座位、不截断、不兜底**。
  人机的名字是**单字**（虎、狼、鹰…，直接复用单机那套字表 `js/ai/ai.js` 的
  `AI_NAME_POOL`，也就是 `meta.botNames`），id 是 `bot:1` 这种。
- **座位不够时「开始游戏」是灰的**（不是"点了被拒"）：`shared/ui/room.js` 按
  `seats < minSeats` 禁用按钮，旁边写"至少要 2 个座位…按「添加人机」补一个"。
  服务端那道闸照旧在（`rooms.start` 只认座位数），真被硬发一条开局命令进来会拒绝并弹提示条。
- **界面的三个新契约**：牌桌头像有**语义圆环**（自己=蓝 / 其他真人=橙 / 人机=灰，
  颜色由平台统一定义），头像自动可点（平台互动），
  音效/特效开关同时接到平台的 `FrpReact.setSound/setFx` 与 `FrpAnim.setEnabled`。
- **服务端一次推来的多条事件是"一条一条演"的**（`FrpAnim.push`，每步 450–700ms，
  顺序/数量/去重不变、不许快进）。
- **不做本地预演 + 演出期间锁输入**（用户点名要的两条，见 `docs/DECISIONS.md` D10）：
  点下去到服务器回包之间，本机**不播任何动画、不出任何音效** —— 画面上"我这一手"
  完全由服务端回放的那一步演出来（预演和回放是两条时间轴，快速连点会看成一团乱）。
  队列没排空（`FrpAnim.busy()`）时，牌桌上**会发 `room.act` 的控件一律当成没点**：
  不发消息、不改界面，同时变灰 + `pointer-events: none`。
  房间级的开始 / 离开 / 邀请 / 加人机、以及 ☰ 菜单和音效开关**不受影响**
